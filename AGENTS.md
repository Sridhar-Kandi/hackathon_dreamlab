# Repository Guidelines

## Keep changes focused

Write only the code the requested task needs. For a small fix, edit the relevant lines and leave unrelated code alone. Add a helper, dependency, or configuration option only when it solves a concrete problem in the current task.

## Write clean, readable code

Use descriptive names, consistent indentation, and familiar syntax. Prefer a simple loop or conditional when a dense expression would make the behavior harder to follow. Use plain language in comments and explain a decision only when the code cannot make its reason clear.

## Skip test cases

Do not create test cases or add test scaffolding. When you need to check a change, run the affected command or try the changed behavior directly.

## Leave out watermarks

Do not add watermarks, generator signatures, or “created with” labels to code, interfaces, assets, or exported files.
